Real vs simulated (v4)

PartStatus
Buttons above (typed identity)Simulation. Anyone can type any name. This is not proof of who is calling.
Signed access (bash run_client.sh demo)Real key proof. The caller signs a one-time challenge (60 s, single use). The server checks the signature, then asks the contract. A typed name, a replayed signature, or another key is rejected.
Who a key belongs toNot verified. Anyone can enroll a key. Nothing links a key to a real person.
Contract / adminTest chain in memory. The admin account is held by this API process.

Easiest: in a second terminal, same folder, run bash run_client.sh demo (uses your key if you already have one, enrolls it if needed, then runs the 3 checks). Single steps: keygen, enroll, access, replay-test, impostor-test. If v4 runs on port 5058, put ZT_PORT=5058 in front of the command. The private key stays in my_key.json on this computer only.
